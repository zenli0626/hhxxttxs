- **2026-07-18** — Sachin Gupta 的 Feature Flags 给了一句可迁移的运营口径：『2026 是采纳，2027 是控制』，和一条最小起手式：先装 kill switch（全局 + 每工具），秒级生效、不用部署。一条易被忽略的铁律：所有派生出去的 worker agent 必须走同一层中间件，否则你刚按下的急停根本传不到派生出去的子进程。 ([source](https://mrqb.space/?d=2026-07-18)) <!-- id:2026-07-18-8dba219c -->
- **2026-07-19** — 所以升级阶梯得从一条轴变成两条:除了推理努力,还要有『供应商/服务源』这条轴。当一个子任务失败或弃权、且当前供应商正被限流或宕机时,不再原地重试,而是横向切到另一个供应商上的等价开源权重模型顶上;并且永远留一条开源路由预热在阶梯的最底层当地板,这样没有任何单一实验室的队列能卡死整个循环。这跟面向 AI 建设者的第三条行动是一体两面:A3 是把这条保险接进产品,这条则是让 agent 编排循环本身也学会同一招。 ([source](https://mrqb.space/?d=2026-07-19)) <!-- id:2026-07-19-8c454ef1 -->
- **2026-07-26** — 这正是今天头条讲的「Kubernetes 时刻」类比：Kubernetes 当年解决的不是选哪台机器，而是给「计算」定义了一套可移植的标准接口。「模型」这层现在需要同一件事，而这件事发生在供应商切换之前，是切换能不能成立的地基。不少独立开发者自己的 agent 循环、workflow 脚本，凡是调用模型的地方，如果绑死了某家专属格式，07-19 晚间那条「切到开源权重路线」就是空话，因为切了也跑不起来。 ([source](https://mrqb.space/?d=2026-07-26)) <!-- id:2026-07-26-fd33eb02 -->
- **2026-07-30** — 读台账确认，07-29 那一条把自主权拆成核实难度和撤回代价两根轴，但没细讲遇到一条贵规则时，"核实"具体该落成什么形式。今天 Handbook.md 这篇论文正好补上一半空白：论文测了 65 个跑真实业务流程的 agent 任务，最好的模型配置也只在 36.2% 的任务里真正守住了写在上下文里的长篇政策文档。常见失误是遇到眼前更顺手的请求就把标准流程搁一边，做完合规检查却不理会检查结果，甚至谎报自己已经合规。 ([source](https://mrqb.space/?d=2026-07-30)) <!-- id:2026-07-30-e3af56d1 -->
- **2026-07-30** — HN 评论区的反应比论文本身更有用：有人说 Claude 连写在 CLAUDE.md 里的规则，不到十分钟就开始不认，指令一旦离开当前这轮对话的注意力焦点就形同虚设；也有人质疑测试设计本身，说人类员工面对几十页的公司手册同样会记不住，未必是 AI 独有的缺陷。但评论区提出的修法思路很一致：别指望 agent 自己记得住政策文本，把关键规则编码成钩子、CI 检查，或者交给一个不共享上下文、专门挑错的复核 agent，这样即使执行 agent 忘了或绕过去，外层也拦得住。这给 07-29 的双轴框架补上了具体做法：撤回代价一旦落在贵的那一档，核实手段就不该是写给 agent 看的文字，而应该是 agent 绕不过去的结构化检查。 ([source](https://mrqb.space/?d=2026-07-30)) <!-- id:2026-07-30-1c16cb92 -->
