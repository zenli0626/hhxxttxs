## ✅ 今日可行动 / Do this today

- 今晚在自己常用的 Claude Code 项目里跑一次 `/doctor`，看看它对你的 CLAUDE.md 和 skills 会给出什么“精简”建议。Anthropic 今天这篇博客等于把自己的评分标准公开了：面向新一代模型，系统提示词里的老规矩，比如“注释不能超过一行”这种死规定，被换成“照抄周围代码的风格”这种更抽象的判断题，Claude Code 的系统提示词因此被砍掉八成以上，跑分反而没掉。具体做法：先跑`/doctor`，把它标出来的冗余、重复、可以交给模型自己判断的部分记下来；然后挑一条你自己写的、管得最细的规则，试着改成一句描述结果长什么样、而不是一步步该怎么做的话，跑一遍原来的任务看输出是不是还稳；如果输出变差了，说明这条细规则暂时不能删，先留着，但你验证过了，不是凭感觉。 *([Hacker News · Anthropic：新一代模型的上下文工程新规](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models))*
- 今晚花十分钟，去查一下你自己那些接了模型 API 的小工具或产品，有没有设置硬性的花费上限。今天 Hacker News 上一篇被扒出的调查显示，有一整条产业链在靠“薅”AI 厂商的免费额度和订阅套餐赚钱：运营者靠拉新用户的免费试用额度、钻订阅套餐“用量不封顶”的空子，把原本值几千美元的官方额度包装成打折套餐转卖。Simon Willison 看完这篇调查后的态度很直接：他希望自己的 LLM 应用能在花到某个金额上限时直接停止工作，而不是等账单爆炸才发现问题。具体做法：翻一下你正在跑的每一个调用模型 API 的脚本或产品，看它现在是不是“没上限、只靠信任”；如果是，去加一个每天或每月的硬性花费上限（大部分供应商控制台都有这个设置），哪怕先加一个到自己邮箱的花费预警也好，别等出问题再补。 *([Hacker News · 调查：AI token转卖产业链如何运作](https://vectoral.com/blog/token-relay-market))*
- 今晚花十分钟，把你自己维护的项目（哪怕只是一个个人项目）里对 AI 辅助贡献的态度写清楚，别留白。Debian 社区这周在投票表决四套方案，从“完全禁止 LLM 辅助的贡献”到“允许，但贡献者要为质量和安全负全部责任、并且披露自己用了 AI”，四套方案吵得很凶，说明连开源社区自己都还没有默认答案。具体做法：翻出你项目的 README 或 CONTRIBUTING，如果上面完全没提 AI 这件事，就借用 Debian 那份“允许但要披露、可担责”的思路，加两三句话，说清楚你允许别人用 AI 辅助贡献到什么程度、要不要披露、出了问题谁负责，别把这件事留给贡献者自己猜。 *([Hacker News · Debian就LLM使用投票，四套方案](https://www.debian.org/vote/2026/vote_002))*

## 🧭 本报社评 / Editorial read

今天五条消息都在追问同一个问题：该给 AI 多少信任，边界画在哪。Anthropic 的答案是往前多迈一步：模型判断力够了，就把管着它的规矩往回收，系统提示词砍掉八成，赌的是模型能接住这份信任。Debian 的答案正好相反：面对同一批工具，一个成熟的开源社区选择往回缩，四套投票方案没有一套是“完全不管”，最宽松的那套也要求披露和担责，等于把“我们还不完全信任无监督的 AI 产出”正式写进社区规则。这两条放在一起说明，“该信 AI 多少”没有统一答案，每个场景自己算账：厂商离模型能力更近，敢往前赌；社区要为下游千万个发行版的可靠性负责，只能往回收。第三条 token 转卖产业链讲的是厂商自己划的信任边界被人找到了漏洞：免费试用和不封顶套餐留出的操作空间，被一整条产业链拿去套利，说明“信任”一旦没有硬性的量化上限兜底，就会被人从数字上找到破绽，光靠信任本身撑不住。斯坦福那份就业数据给整个讨论泼了一盆冷水：不管厂商还是社区吵得多凶，这套“该给 AI 多少空间”的问题反映到真实就业市场上的幅度其实很小，唯一站得住脚的冲击集中在应届生这一小群人身上，说明舆论对 AI 能力和影响的想象，走在了真实证据前面很远。最后 FLUX-mimic 提醒一句：这场关于“信任边界画在哪”的讨论，很快就不只发生在代码和聊天记录里了，视频模型的能力已经能直接喂给机器人做动作控制，而且已经进了真实工厂测试，边界要往物理世界挪的时候，出错的代价会比多写一行注释或者转卖几个 token 贵得多。

*Line up today's five items and they're all answering the same question: who gets to decide how much trust to extend to AI, and where the line gets drawn. Anthropic's own answer is to lean further in: now that the model's judgment is good enough, pull back the rules governing it, cut the system prompt by 80%, and bet that the model can carry that trust. Debian's answer runs the opposite direction: facing the same tools, a mature open source community is pulling back instead. None of its four competing vote proposals says do nothing, and even the loosest one demands disclosure and accountability, formally writing we don't fully trust unsupervised AI output yet into community policy. Put side by side, these two show there's no single answer to how much to trust AI; it's a calculation each context makes for itself. A vendor sitting closer to the model's own capability can afford to bet forward, while a community responsible for the reliability of thousands of downstream distributions can only pull back. The third item, the token resale industry, is what happens when a vendor's own trust boundary has a hole in it: the room left open by free trials and uncapped usage tiers got found and arbitraged by an entire supply chain, showing that trust without a hard, quantified ceiling behind it eventually gets picked apart at the numbers. Stanford's jobs data throws cold water on the whole argument: however loudly vendors and communities are fighting over how much room to give AI, the real-world jobs market has barely moved, with the one impact that actually holds up concentrated on a narrow slice of recent graduates, meaning public imagination about AI's capability and impact is running well ahead of the actual evidence. The last item, FLUX-mimic, is a reminder that this argument over where to draw the trust boundary won't stay confined to code and chat logs much longer. A video model's capability can now feed straight into robot motor control, and it's already being tested on a real factory floor, and once the boundary moves into physical space, the cost of getting it wrong is a lot higher than an extra line of comments or a few resold tokens.*

## 🆕 今日所学 / What I learned

- 读台账确认，最近十条主线都在解“怎么运行一个多 agent 循环”这一轴：评测分级、效果分层、供应商容错、证据分级、harness 可移植性审计。今天 Anthropic 官方博客给了一个不同轴的信号：管住模型的规矩本身也该跟着模型代际往回收，不是所有代际都该用同一套 prompt 写法。老一代模型需要密集规则和例子才能管住输出，新一代模型（Opus5 这一档）判断力已经足够强，继续堆规则只会浪费上下文；Anthropic 自己把 Claude Code 给新模型用的系统提示词砍掉了八成以上，跑分没掉。
- 回头看不少 AI 编辑类项目里实际在用的 skill 文件，写法明显偏老派：大量条文式的硬规则（比如对 banner 字数、action 数量、每个字段要不要_en 都有精确规定），例子和反例塞得很满，同一条要求在不同小节里会重复出现。Anthropic 这篇文章点名的三种可以精简的地方——规则改判断、例子改接口设计、一次性塞满改按需加载——在这类 skill 里都能找到对应的位置，具体怎么改，值得找个时间专门过一遍、动手精简。
