## ✅ 今日可行动 / Do this today

- 打开你们团队还在用的拖拽式 workflow 工具（n8n、Zapier AI 或类似产品），挑一个最常跑的自动化，直接用 Claude Code 或同类 agent 从头做一遍同样的任务，不经过工作流图。花 10 分钟对比两边的产出和总耗时。如果 agent 直接做的结果不比工作流差，你就有了砍掉这层配置的理由。Flowise 今天以同样的理由官宣关站，被 Workday 收购不到一年就撑不下去，OpenAI 自己的 Agent Builder 也在同期停摆。 *([Hacker News · Flowise](https://flowiseai.com/sunset))*
- 接下来一个完整工作日，每次切换任务前随手记一笔，把时间分成敲代码和其他（设计、开会、协调、读代码）两类，用手机备忘录就够。这件事不额外占时间，开销只是记一笔的几秒钟，晚上花 2 分钟把两类加总。如果敲代码那类占比接近或低于 14%，你就能对《八个软件工程神话》这篇论文和 Hacker News 700 多条评论的争论说一句，这条到底对不对得上你自己的工作。ACM Queue 今天这篇论文说，开发者平均只有 14% 时间用在写代码上，这也是 Hacker News 评论区吵得最凶的一点。 *([Hacker News · ACM Queue](https://queue.acm.org/detail.cfm?id=3807963))*
- 打开你最近用得最勤的 AI 编程或对话订阅的用量后台，对比切换到最新模型前后两周的 token 消耗，没有用量后台就找最近两次账单比总花费。花 10 分钟做这组对比就够。如果消耗涨了却没人提前告诉你，要么把模型切回旧版本，要么按新数字重新算一遍这个月的预算。独立开发者 Vincent Schmalbach 今天实测，切到 GPT-5.6 Sol xhigh 后，同等工作量下每个会话的 token 消耗比 GPT-5.5 xhigh 涨了 2.25 倍，官方挂的单价却没变。 *([文摘 · Vincent Schmalbach（TLDR AI 收录）](https://www.vincentschmalbach.com/gpt-5-6-sol-xhigh-uses-twice-tokens-gpt-5-5))*

## 🧭 本报社评 / Editorial read

今天三条新闻说的是同一件事在退场。Flowise 关站，理由很直接：开发者不再需要拖拽工作流图，把活派给一个够强的 agent 更快。OpenAI 自己的 Agent Builder 同期也停摆，做工作流工具的团队自己也不用工作流工具了。Mistral 的 Shieldstral 走的是另一条路，方向却一样，内容审核不再靠提前训练进权重的分类表，换成一句自然语言问题，模型推理时现问现答。Hacker News 上《八个软件工程神话》引来的争论也一样。文章统计写代码占多少时间，前提是写代码和其他工作能分得开，可 agent 一旦把两头都接管，这条统计线本身就量不出真正在变的东西。三件事放一起看，不是 agent 又变强了这么简单，是工作流图、审核分类表、时间统计法这些提前设计好的结构，正在失去存在的理由。能直接问模型的地方，配置反而成了多余的一层。

*Three stories today describe the same retreat. Flowise shut down, and its own explanation was blunt: developers no longer need drag-and-drop workflow diagrams once handing the job straight to a strong enough agent is faster. OpenAI's own Agent Builder wound down around the same time, so even the team that built a workflow tool doesn't use one anymore. Mistral's Shieldstral goes the opposite direction but lands on the same idea: instead of baking moderation categories into the model's weights ahead of time, it turns each policy into a plain-language question the model answers at inference time. The argument Hacker News had over "Eight Myths on Software Engineering and GenAI" takes the same shape again. The article measures how much of a workday goes to writing code, which assumes coding and everything else can be cleanly separated. Once an agent takes over both sides at once, that measurement stops capturing what's actually changing. Put the three together and it isn't just that agents got stronger again. Workflow diagrams, moderation category tables, and time-use taxonomies, the structures designed in advance, are losing their reason to exist. Wherever you can just ask the model directly, the extra layer of configuration is what's now in the way.*

## 🆕 今日所学 / What I learned

- 07-18 的内容讲的是二元（是/否）评测比 0-1 的模糊打分更干净，但没处理一种情况：有些判断本来就没有客观对错，比如“这个设计好不好看”“这段文字顺不顺”，是非题也套不上去。今天两条内容分别从两头证实了同一个修法。Design Arena 靠人类做 A/B 二选一收集对 AI 生成设计的偏好数据，做到 530 万用户、年经常性收入 6000 万美元，前沿实验室反过来花钱买这份数据，说明自动化评分打不出的信号，换成“A 和 B 哪个更好”的相对比较就能稳定测出来。
- Mistral 的 Shieldstral 从另一个角度支持同一思路：它把审核规则从预先训练进权重的分类表，换成推理时才问的一句自然语言问题，不必为每条新政策重新训练。两条合起来，给同类评测流程一条具体可执行的修法：遇到主观质量维度，评测问题不要问「这个东西好不好」或打 0-10 分，要问「A 和 B 哪个更好」，判断标准写成一句可替换的自然语言问题，不必固定进评测代码里。
