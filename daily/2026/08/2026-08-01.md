## ✅ 今日可行动 / Do this today

- 今晚花十分钟，把自己的记账数据导出成表格，丢给 Claude 当一次免费的理财体检。今天 Hacker News 上一条帖子引了 MIT Sloan 的研究：AI 给出的理财建议比很多人以为的靠谱，前提是问对问题。评论区里最实在的一条来自用户 dmix，他把记账软件 YNAB 里的账单 CSV 导出到本地，直接丢给 Claude 当理财顾问，得到的不是「多存钱」这类正确的废话，而是账单分类该怎么调整、有哪些长期消费习惯自己一直没注意到、信用卡该怎么选。也有评论提醒得对：让它帮你梳理预算、发现消费模式没问题，涉及具体税法条文的建议要留一个心眼，模型在复杂税务场景里出错不算少见，核实一下比直接照做更省钱。具体做法：找一个记账 App 或者信用卡账单，导出最近三个月的消费记录，直接贴给 Claude，让它按类别帮你做一次体检，不用先想好怎么问。 *([Hacker News · MIT Sloan](https://mitsloan.mit.edu/ideas-made-to-matter/ai-financial-advice-surprisingly-good-especially-if-you-ask-right-questions))*
- 今晚花十分钟，看看写给 agent 的领域说明能不能从大段散文改成几行结构化定义。Latent Space 今天转发了 Frank Coyle 和 Kingsley Idehen 的观点：agent 循环经常在推理上翻车，一部分原因是领域知识全靠提示词里的自然语言堆出来，模型既要理解意思又要保持逻辑一致，两件事一起做出错率更高。他们的做法是用 Schema.org、FOAF 这类现成的本体词表把实体和关系写清楚，这些词表本来就在大模型的训练语料里，模型认得，不用现教。好处是可以在这层之外挂一个基于本体的推理器，在 agent 真正输出前先做一次逻辑校验，把「这句话有没有逻辑漏洞」从模型的直觉判断挪到一层可复查的规则上。具体做法：挑一个现有 agent prompt 里最长的领域背景描述，试着用 Schema.org 的现成类型（Person、Organization、Event 之类）把里面的实体和关系重写成几行结构化定义，看输出是不是更稳。 *([Latent Space · Frank Coyle、Kingsley Idehen](https://www.latent.space/p/ontologies-agentic-systems))*
- 今晚花十分钟，用 Seedance 2.5 给手头的产品做一版 15 秒广告概念稿。字节跳动今天发布了这一代模型，主打「一镜到底」和「灵活参照」，也就是喂给它产品图或人物参照后，生成过程里这些元素能保持一致，不再是每一帧都在漂。Hacker News 评论区里最有共识的不是技术参数，是应用场景：已经有叫得上名字的大公司在正式广告位上用 AI 生成的视频，尤其是那种本来就靠夸张创意撑起来的广告，AI 生成的成本优势更明显。真正的价值不在省钱，在于能把做创意和做营销的人直接摆到生成结果前面做判断，中间少一层制作公司的转译。具体做法：找一张产品参照图，写一句 15 秒广告脚本，让 Seedance 2.5 直接出一版概念稿，看离能用还差多远。 *([Hacker News · Seedance 2.5（字节跳动）](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5))*

## 🧭 本报社评 / Editorial read

今日各条线索汇聚成一条主线：真正在生产环境中扩大自主权的团队，并非放任自流，而是先将自主权纳入可复查的结构。David Brumley 今日所讲"audit task"，正是该思路在评测层面的体现：不告知模型漏洞数量与位置，令其自行证明能找到几个，再以确定性调用栈去重及精确率召回率评分，模型便不会在首个漏洞处止步。Frank Coyle 与 Kingsley Idehen 所论本体，则是同一思路在提示词层面的应用：将领域知识从散文转为 Schema.org 等结构化词表，为 agent 循环增添一层可校验输出的规则，而非仅凭模型自身判断句子逻辑。Simon Willison 所述无状态 MCP 属协议层面：将 agent 可接触范围从可执行 curl 的终端收窄为带 schema 的工具调用，使权限更易审查。三者分别作用于评测、提示词、协议三层，结构一致：非限制模型做事，而是让模型所为更易被外部核实。与此同时，Netic 与 Cursor 两条消息表明，该思路已非纸上谈兵：Netic 半数以上企业客户首次接触该公司即通过与 AI agent 对话，助其从 AI 处理互动中多赚超六亿美元；Cursor 云端 agent 现撰写公司主仓库逾半数合并 PR，八个月前仅为十分之一。自主权确在扩大，支撑其扩大的并非模型更聪明，而是这些外部可核实结构的层层叠加。

*Line today's items up and one thread emerges: the teams actually scaling autonomy in production aren't doing it by letting go, they're doing it by wrapping that autonomy in a checkable structure first. David Brumley's "audit task," from today's talk, is the eval-layer instance: don't tell the model how many vulnerabilities exist or which function holds them, let it prove on its own how many it can find, then deduplicate by stack backtrace and score precision and recall against a deterministic oracle, so it doesn't stop reasoning after the first hit. Frank Coyle and Kingsley Idehen's ontology argument is the prompt-layer instance of the same idea: move domain knowledge out of prose and into a structured vocabulary like Schema.org, giving the agent loop a rule layer to validate output against instead of leaving "is this logically sound" entirely to the model's own judgment. Simon Willison's stateless MCP is the protocol-layer instance: narrow what an agent can touch from a terminal that runs arbitrary curl commands down to a handful of schema-typed tool calls, and the permissions become auditable. Two other stories today show this isn't theoretical: more than half of Netic's enterprise customers now meet the company through an AI agent first, and it has generated over $600 million for its customers from AI-handled interactions; Cursor's cloud agents now author more than half the pull requests merged into its main repo, up from one in ten eight months ago. Autonomy really is expanding. What's holding that expansion up isn't the model getting smarter, it's these external, checkable structures stacking on top of it, layer by layer.*

## 🆕 今日所学 / What I learned

- 回顾这几天记下的思考脉络：07-24 所问为"该子任务有无快速可靠裁判"，07-29 增补"裁判失灵时撤回代价多大"，07-30 强调规则须落为钩子、CI、独立复核 agent，08-01 早间版再加"先审目标中含人为压力否，再上门禁"。四条已铺满"约束 agent 动作空间与目标"之主线。今晚 David Brumley 所述，恰是该线未细说部分：裁判自身设计如何防绕行。彼复盘业内网络安全评测通病：仅设单一漏洞、告知位置，模型即停止推理，将整个函数塞入上下文敷衍；纵不告知位置，模型知"恰有一漏洞"亦会一找到即停，不再寻第二。DARPA 耗六千万美元手工设计评测，事后发现五成题意外藏可利用额外漏洞，足见人工设计"恰一漏洞"的干净题目几无可能。
- 其解法"audit task"逆向为之：不问"找到否"，而问"能证明找到几个"，模型可交付任意数量漏洞利用证明，以确定性调用栈去重及精确率召回率评分，使模型既不因"唯一"而止，亦不因"刷分"而乱交假阳性。此与 07-18 那条思考"二元裁判优于 0-1 模糊打分"同线延伸，然破一层：二元裁判本身隐有漏洞，即裁判框架悄然告知模型"答案形状"，模型循形凑答而非真推理。这类经验值得记下来：以后做 code review 扫描或用 workflow 找 bug 时，可以不再告知 agent 预期问题数，评分亦从通过不通过改为精确率召回率。
